# Platform Update Process

1. Read Microsoft Learn, provider, and module release notes.
2. Create a branch and update one dependency group at a time.
3. Run formatting, initialization, validation, tests, security scanning, and link checks.
4. Generate plans for every supported profile.
5. Review replacements, policy changes, API changes, and cost impact.
6. Test in a non-production tenant or subscription.
7. Obtain approval and apply through the controlled pipeline.
8. Validate Azure resources and operations.
9. Update the review record, diagrams, and decision log.

Do not describe a pinned version as permanently current. Pinning supports repeatability; maintenance keeps the platform current.
